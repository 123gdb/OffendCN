# OffendCN: Chinese Online Offensive Language Detection

This repository contains the code and data for our study on Chinese online offensive language detection. It covers three parts:

1. **Fine-tuning & Knowledge Augmentation** (`src/finetuning/`) — single-task fine-tuning of Chinese RoBERTa on offensive identification, target category, expression type, dialect group, and dialect-offensive binary classification. On top of this, target, dialect, and pinyin vocabularies are introduced as additional knowledge branches for knowledge augmentation, together with a TextCNN baseline and multi-task learning (MTL) ablations.
2. **LLM Prompting** (`src/prompting/`) — 0-shot and 5-shot evaluation of ChatGLM3-6B and Qwen3-14B, both served locally through Ollama, on the five tasks.
3. **Quadruple Extraction** (`src/extraction/`) — given a gold Target Category, an LLM extracts the `Target / Argument / Offensive_Span` triple; predictions are scored automatically with BERTScore and Soft-F1. Evaluated models: LLaMA3-8B, DeepSeek-R1-14B, ChatGLM3-6B and Qwen3-14B, all served locally through Ollama.

## Installation

```bash
pip install -r requirements.txt
```

**Important (Windows): always `import torch` before `import transformers`.** Otherwise `sentencepiece` crashes while loading the tokenizer. Keep this order when editing imports.

All LLMs are served locally through [Ollama](https://ollama.com) (`http://localhost:11434`) and are not included in this repository — download them yourself. Prompting uses `qwen3:14b-Q4_K_M` and `chatglm3:6b`; quadruple extraction uses `llama3:8b` and `deepseek-r1:14b`. Any other Ollama model works as well, as long as its tag is passed with `--model`.

## Dataset

`data/OffendCN.json` is the dataset constructed and annotated by the authors. It contains **20,015** samples with the following fields:

| Field | Description |
| --- | --- |
| `ID` | Sample identifier |
| `content` | Raw text |
| `platform` | Source platform |
| `topic` | Topic |
| `offensive` | Whether the text is offensive (bool) |
| `offensive_type` | `Tar-off` (targeted) or `Gen-off` (generic); empty string when `offensive=false` |
| `four_tuple` | Quadruple with `Target`, `Argument`, `Offensive_Span`, and `Target_Category` (one of `Gender` / `Region` / `Race` / `LGBTQ` / `Other`); populated only for `Tar-off`, otherwise `{}` |
| `dialect_info` | Present only when `offensive=true`, with `is_dialect_offensive` (bool) and `dialect_group` (empty string for standard Mandarin); `{}` when `offensive=false` |
| `expression_type` | `Explicit` / `Implicit` / `Reported`; populated only for `Tar-off`, otherwise an empty string |

The three subsets and the split files are **not committed** (ignored via `.gitignore`). Running `python src/prompting/make_splits.py` once generates both `data/subsets/` (three raw subsets) and `data/splits/` (twelve split files), which the other scripts read directly:

| Subset file | Filter | Samples |
| --- | --- | --- |
| `subsets/offensive_data.json` | `offensive == True` | 6,371 |
| `subsets/targeted_offensive_data.json` | `four_tuple` is an object containing `Target_Category` | 5,327 |
| `subsets/dialect_offensive_data.json` | `dialect_info.is_dialect_offensive == True` | 780 |

The input of quadruple extraction is fixed to `data/subsets/targeted_offensive_data.json` (the 5,327 samples above). It is resolved by `src/common/paths.py`, so no manual copying is required.

Data splits:

- **Fine-tuning** (`finetune.py`, `textcnn.py`, `multitask.py`) generates splits at runtime: an 8:1:1 stratified split with `SPLIT_SEED = 42`, not written to disk. `finetune.py --task offense` and `multitask.py` read `data/OffendCN.json` directly; the remaining tasks read `data/subsets/` (generated by `make_splits.py`).
- **Prompting** uses `src/prompting/make_splits.py` with `SEED = 42` to write splits into `data/splits/` (run once before evaluation): `train/dev/test.json` (offensive identification), `target_train/dev/test.json` (target category, also used for expression type), `dialect_train/dev/test.json` (dialect group), and `dialect_bin_train/dev/test.json` (dialect-offensive binary classification). The expression-type task reuses the `target_*` splits, hence no separate `expression_*` files. Splits are fully seed-determined, and regenerated files are sample-for-sample identical to those used in the paper.

## Reproducing the Experiments

Run the following once before anything else (all three parts depend on it):

```bash
python src/prompting/make_splits.py    # generates data/subsets/ and data/splits/
```

### Fine-tuning & Knowledge Augmentation

```bash
cd src/finetuning

# Baseline / knowledge augmentation
# task: offense|target|expression|dialect|dialect_binary
# mode: baseline|target|dialect|pinyin|full
python finetune.py --task offense --mode baseline
python finetune.py --task expression --mode full

# TextCNN baseline
python textcnn.py --task offense

# Multi-task learning and ablation
python multitask.py
python ablation.py
```

### LLM Prompting

```bash
cd src/prompting

# Run once before evaluation: writes the 12 split files under data/splits/
python make_splits.py

# ChatGLM3-6B (task: offense|target|expression|dialect|dialect_binary, shot: 0|5)
python eval_chatglm.py --task offense --shot 0

# Qwen3-14B (Ollama must be running)
python eval_qwen.py --task target --shot 5
```

Predictions and metrics are written to `results/`.

Both scripts share `src/prompting/prompts.py`, which defines the instruction, the label space, the five few-shot examples (selected deterministically from the training splits) and the answer parser. Both models are served through Ollama with the same decoding settings (`temperature=0`, `num_ctx=8192`), so ChatGLM3-6B and Qwen3-14B see exactly the same prompt under the same inference configuration and are directly comparable. Model-specific prompt variants used in earlier development are not retained, so numbers produced by older versions of these scripts should not be mixed with new runs.

### Quadruple Extraction

```bash
cd src/extraction

# batch prediction with any Ollama model; the tag is part of the output filename
python generate_ollama.py --model llama3:8b
python generate_ollama.py --model deepseek-r1:14b
python generate_ollama.py --model chatglm3:6b
python generate_ollama.py --model qwen3:14b-Q4_K_M

# BERTScore / Soft-F1 evaluation
python evaluate.py --input llama3-8b_quadruple_predictions.json
```

`generate_ollama.py` writes `<model-tag>_quadruple_predictions.json`, where `:` and `/` in the Ollama tag are replaced by `-` (e.g. `llama3:8b` → `llama3-8b_quadruple_predictions.json`). All models share the same prompt template and the same decoding settings (`temperature=0`, `num_ctx=8192`, `num_predict=512`), so their predictions are directly comparable. `evaluate.py` reads the file given by `--input` (default: `llama3-8b_quadruple_predictions.json`).

## Pre-trained Backbones

The following backbones are not included. Download them from Hugging Face and place them under `models/` (create the directory if it does not exist; `models/` is ignored by `.gitignore`). Directory names must match the table below (`MODELS_DIR` in `src/common/paths.py`):

| Directory | Usage |
| --- | --- |
| `chinese-roberta-wwm-ext-base` | main backbone for fine-tuning and extraction evaluation |
| `bert-base-chinese` | comparison backbone |
| `chinese-macbert-base` | comparison backbone |

LLM prompting and quadruple extraction require the Ollama models only (`qwen3:14b-Q4_K_M`, `chatglm3:6b`, `llama3:8b`, `deepseek-r1:14b`, or any other tag passed to `--model`)
